**ตอนนี้:**
- การ์ดเดิม (ตำแหน่งเดิม) เหลือแค่ **บอกว่าตอนนี้เลือกอะไรอยู่** + ปุ่ม「เปลี่ยน」

- **คำเตือน "ทีมที่กระจายไว้แล้วจะถูกทับ" ย้ายมาอยู่ในใบเดียวกัน** — ไม่มี modal ซ้อนอีก
- ค่าเริ่มต้น = "แยกตามทีม" เสมอ และรีเซ็ตทุกครั้งที่โหลดข้อมูล (ไม่จำข้ามงวด)

**ไฟล์:** `frontend/index.html` (การ์ด) · `frontend/app.js` (`openAllocScopeModal`,

## 2) หน้ารวมภาค — บวกเป้าทั้งภาค (เลิกเลือกทีมเจ้าของเป้า)

### สิ่งที่เจอระหว่างทำ (สำคัญ)

โหมด "รวมทั้งหน่วย" **เดิมคำนวณผิดสเกล**: ส่ง `yellowTargets` ของพนักงาน *ทั้งภาค*
ไปคู่กับ **เป้าหีบของทีมเดียว** (ทีมที่เลือกใน dropdown) → เป้าเงินกับเป้าหีบคนละเท่าตัว
`_revenue_scale_factor` เพี้ยน และเป้ารวมบนตาราง (ผลบวกทั้งภาค) ไม่ตรงกับที่ server pin ไว้
ทำให้ `autoRebalance` ฝั่ง browser ไปอัดหีบเพิ่มทั้งภาคทันทีหลังกระจาย — **การแก้รอบนี้ปิดรูนี้ไปด้วย**

### ที่แก้

**Backend**
- `backend/core/targets.py` → `load_summed_target_boxes(sup_ids, month, year)`
  บวก `supervisor_target_boxes` ต่อ SKU ข้ามทีม · คืน `(df, รายชื่อทีมที่ไม่มีไฟล์เป้า)`

## 3) คลิกช่องหีบ = ล็อกค่าไว้

**เดิม:** `onResultEdit` มีสาขา "คลิกแล้วเลขไม่เปลี่ยน = ไม่ถือว่าแก้" ผลคือ
**ผู้ใช้ไม่มีทางบอกระบบได้เลยว่าช่องไหนห้ามขยับ** เลขที่ตั้งใจคงไว้จึงถูกเกลี่ยหาย
ตอนไปแก้ช่องอื่น

**ตอนนี้:** คลิกเข้าไปในช่องแล้วคลิกที่อื่นโดยไม่แก้เลข → `is_edited = true`
- ช่องขึ้นสี「แก้แล้ว」+ ปุ่ม ↺ โผล่ทันที (ไม่ต้อง render ทั้งตาราง — `_syncCellRevertButton`)
- toast บอกว่าล็อกที่กี่หีบ และกด ↺ เพื่อปลดล็อก
- ตัวเกลี่ยหยิบเฉพาะช่องที่ยังไม่ล็อก · รอบคำนวณใหม่ส่งค่านี้เป็น `locked_edits`
- ↺ ที่ช่องล็อกเปล่า ๆ = "ปลดล็อก" (ข้อความ toast แยกจาก "คืนค่าเดิม")

**หมายเหตุที่ควรรู้:** ช่องที่ยังไม่มีแถวผลกระจาย (แสดง 0) ไม่สร้างแถวใหม่จากการคลิก —
ช่องพวกนั้นตัวเกลี่ยแตะไม่ได้อยู่แล้ว จึงเท่ากับถูกล็อกโดยปริยาย

## 4) ผู้จัดการรายภาคระบุ "หน่วย" (credit/van)

- `user_access_store.canonical_row` — `acc_unit` เก็บได้เมื่อเป็นซุป **หรือ**
  ผู้จัดการ `manager_level = regional` · ระดับ `division` ยังตัดทิ้ง (ขอบเขตคือทั้งดิวิชันอยู่แล้ว)
- `access_hierarchy.compute_visible_supervisors_for_row` — ผู้จัดการที่ระบุหน่วย
  เห็นเฉพาะซุปหน่วยเดียวกัน **แต่ยังเห็นรหัสตัวเอง** (ถ้ากรองทิ้งจะล็อกอินมาแล้วว่างเปล่า)
- หน้าแอดมิน: ช่อง「หน่วย」โผล่ตามกฎเดียวกัน (`_adminUnitFieldAllowed` ตรงกับ backend)
  ทั้งใน modal เพิ่มผู้ใช้และการแก้ในตาราง · เปลี่ยนระดับ Mgr แล้วช่องโผล่/หายทันที
- **แก้บั๊กพ่วง:** เดิมส่ง `acc_unit: null` ตอนล้างค่า ซึ่ง backend แปลว่า "ไม่แตะฟิลด์นี้"
  → **ล้างหน่วยทิ้งไม่ได้เลย** (ทั้งของซุปด้วย) ตอนนี้ส่งสตริงว่างแทน

## 5) บัญชีแอดมินอย่างเดียวล็อกอินไม่ได้ — เจอต้นเหตุจริง

**ต้นเหตุ:** แถวที่ไม่มีรหัสขายเก็บ `userpl` เป็น sentinel `"none"` ในไฟล์
(ทุกฟิลด์ต้องมีค่า) แต่ฝั่งสิทธิ์อ่านดิบแล้ว `.upper()` → ได้ **รหัสทีมปลอมชื่อ `"NONE"`**
ไหลเข้า `allowed_supervisor_codes`, รายชื่อทีมในหน้าล็อกอิน และลำดับชั้นทั้งระบบ
แอดมินจึงเห็นตัวเลือกทีมที่โหลดไม่ได้ ส่วนคนอื่นก็เห็น `NONE` โผล่

**ที่แก้ (backend):**
- `user_access_store.real_userpl()` — helper กลาง คืน `""` ให้ sentinel
- `access_control.load_acc_rows()` และ **ทุกจุดใน `access_hierarchy.py`** ใช้ helper นี้

**ที่แก้ (frontend):**
- `S.loginPickCount` + `_isAdminOnlyAccount()` = มีสิทธิ์แอดมิน แต่ไม่มีทีมให้เลือกสักรายการ
- บัญชีแบบนั้น **เข้าหน้าแอดมินให้เลย** (แบบเดียวกับที่ marketing ทำอยู่)
  ไม่ต้องเจอ "ดึงรายการไม่สำเร็จ — ลองกดรีเฟรช" ทั้งที่ระบบทำงานปกติ
- แอดมินรายภาคที่ **มี** ทีม ยังได้ฟอร์มล็อกอินปกติเหมือนเดิม (สิทธิ์แอดมินซ้อนทับตำแหน่ง)

> ⚠️ บัญชีแอดมินรายภาคยังต้องมี `acc_region`/`acc_division` ในไฟล์ ไม่งั้น backend
> ปฏิเสธแบบ fail-closed (ตั้งใจ) — ถ้าเข้าหน้าแอดมินแล้วทุกอย่าง 403 ให้ไปเติมสองฟิลด์นี้
