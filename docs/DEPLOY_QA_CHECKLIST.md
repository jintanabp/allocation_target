## 7. ผู้จัดการ — รวมภาค

| # | ขั้นตอน | ผล | หมายเหตุ |
|---|---------|-----|----------|
| 7.1 | มุมมองรวมภาค — composite legend | | |
| 7.2 | กระจายรวมภาค + บันทึก snapshot ต่อ SL | | |
| 7.3 | **ล็อกไม่ข้ามทีม** — หาภาคที่มี ≥2 ทีมและมี `emp_id` ซ้ำกัน · แก้ตัวเลขในทีม A แล้วคำนวณใหม่ · **ทีม B ต้องไม่เปลี่ยน** | | |
| 7.4 | **ไม่มี snapshot ลงรหัสผู้จัดการ** — หลังกระจายรวมภาค ตรวจ `data/allocations/` ต้องมีแต่ไฟล์ของ SL จริง ไม่มีไฟล์ชื่อรหัส manager | | |
| 7.5 | **คำเตือน fallback ไม่หาย** — ถ้ามีทีมใดตกไปใช้ proportional แถบ「ขอให้รีเช็ค」ต้องขึ้นและ**ระบุชื่อทีม**นั้น แม้ทีมสุดท้ายจะปกติ | | |
| 7.6 | **สำเร็จบางส่วน** — ทำให้ทีมหนึ่งพัง (เช่นลบ cache เป้าของทีมนั้น) · ทีมที่เหลือต้องยังกระจายและบันทึกได้ + ขึ้นรายชื่อทีมที่พลาด | | |
| 7.7 | โหลดรวมภาคเร็วขึ้น — จับเวลาเทียบกับ `AGGREGATE_LOAD_WORKERS=1` | | |
| 7.8 | **แถวรวมทีม** — ตารางรวมภาคมีแถวสรุปท้ายกลุ่มของแต่ละซุป · หลังกระจายใหม่ต้องขึ้น「ตรงเป้าทีมทุก SKU」ทุกทีม | | |
| 7.9 | **ย้ายหีบข้ามทีมแล้วเห็น** — เพิ่มหีบให้คนในทีม A · แถวรวมทีม A ต้องขึ้น `+n` สีส้ม และทีมที่ถูกดึงต้องขึ้น `-n` สีน้ำเงิน | | |
| 7.10 | กด **คำนวณใหม่** หลังย้ายข้ามทีม — ทุกทีมกลับมา「ตรงเป้าทีมทุก SKU」 | | |
| 7.11 | **ขอบเขตเป็น modal** — กด「เริ่มคำนวณ」ต้องเด้ง modal สองตัวเลือกก่อนเสมอ · กดยกเลิกแล้วต้องไม่คำนวณ | | |
| 7.12 | **ไม่มีช่องเลือกทีมเจ้าของเป้า** — ในโหมด「รวมเป้าทั้งภาค」ต้องไม่มี dropdown ให้เลือกทีมอีก | | |
| 7.13 | **เป้ารวม = ผลบวกทุกทีม** — เลือก「รวมเป้าทั้งภาค」แล้วกระจาย · แถวเป้ารวมท้ายตารางต่อ SKU ต้องเท่าผลบวกเป้าของทุกทีมพอดี | | |
| 7.14 | **ทีมไหนไม่มีไฟล์เป้า = ปฏิเสธ** — ลบ `data/target_boxes_<SL>_<ปี>_<เดือน>.csv` ของทีมหนึ่ง แล้วเลือก「รวมเป้าทั้งภาค」· ต้องขึ้น error ระบุชื่อทีม ไม่ใช่คำนวณต่อด้วยเป้าที่ขาด | | |
| 7.15 | **คลิกช่องแล้วล็อก** — คลิกเข้าไปในช่องหีบแล้วคลิกที่อื่นโดยไม่แก้เลข · ช่องต้องขึ้นสี「แก้แล้ว」+ ปุ่ม ↺ และ toast บอกว่าล็อกแล้ว · แก้ช่องอื่นในแถวเดียวกันแล้วช่องที่ล็อกต้องไม่ขยับ | | |
| 7.16 | กด ↺ ที่ช่องที่ล็อกไว้ — ต้องปลดล็อก (toast บอก「ปลดล็อก」) และระบบเกลี่ยช่องนั้นได้อีก | | |

## 10. หลัง `git pull` บนเซิร์ฟเวอร์

| # | ขั้นตอน | ผล | หมายเหตุ |
|---|---------|-----|----------|
| 10.1 | **ตรวจปลายทาง Target Sun 1 ครั้ง** — เข้าหน้าแอดมิน > แหล่งข้อมูล ดูว่า preset (test/uat/prod) ยังเป็นค่าที่ต้องการ | | |

> ทำไมต้องตรวจ: `config/app_runtime.json` เก็บปลายทางที่จะส่งข้อมูลจริง
> ถ้าไฟล์นี้ยัง track ใน git อยู่ การ pull จะเขียนทับค่าที่แอดมินตั้งไว้เงียบ ๆ
> ทางแก้ถาวรคือรัน **ครั้งเดียว** แล้ว commit:
>
> ```
> git rm --cached config/app_runtime.json
> ```
>
> (`.gitignore` เตรียมบรรทัดไว้แล้ว · ต้นแบบอยู่ที่ `config/app_runtime.example.json`)
> หลังรันคำสั่งนี้ การ pull ครั้งถัดไปจะ **ลบไฟล์ออกจากเครื่องเซิร์ฟเวอร์** ค่าจะกลับไปเป็น
> ค่าเริ่มต้น จึงต้องเข้าไปตั้ง preset ใหม่ในหน้าแอดมินอีก 1 ครั้ง — หลังจากนั้นจะไม่โดนอีกเลย
