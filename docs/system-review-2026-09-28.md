## 1. ความปลอดภัยและสิทธิ์ (auth / RBAC)

### 1.1 แอดมินยกสิทธิ์ตัวเองผ่าน `PUT /admin/user-access` ด้วย `new_email` [สูง]
- **ที่:** `backend/routers/admin.py:344-400` (`update_user_access`)
- **ปัญหา:** โค้ดทำ `updated_row = dict(existing)` แล้วเปลี่ยน email/userpl ฟิลด์ `role`, `admin_scope` และ `can_import_targetsun` ติดไปกับแถวครบ ขั้นนี้ไม่เรียก `ensure_can_assign_role` เลย
- **ผลกระทบ:**
  - แอดมินที่ขอบเขตครอบแถวของ head_admin หรือ dev ย้ายแถวนั้นมาเป็นอีเมลตัวเองได้ แล้วได้ role นั้นมาเลย
  - หรือย้ายแถวของ supervisor ในขอบเขตมาเป็นของตัวเอง ได้สิทธิ์ส่ง TargetSun ของทีมนั้น และตัดสิทธิ์เจ้าของจริงไปพร้อมกัน
- **ทางแก้:**
  - ห้ามคนที่ไม่ใช่ dev แตะแถวที่มี `role`
  - ห้ามเปลี่ยนอีเมลของแถวให้เป็นอีกคน
  - ห้ามแก้แถวของอีเมลตัวเอง ใช้กฎเดียวกันกับ POST, PUT, DELETE และ `/user-access/targetsun`

### 1.3 ส่ง TargetSun ทับเป้าพนักงานของทีมที่ไม่มีสิทธิ์ได้ [กลาง-สูง]
- **ที่:** `backend/routers/lakehouse.py:288-383` ตรวจแค่ `req.sup_id` ส่วน `services/lakehouse.py:2427-2455` เติม grain ข้ามทีม (`_read_tga_grain_across_teams`) ให้ทุก `emp_id` ในคำขอ

- **ทางแก้:** บังคับให้ `emp_id` ทุกคนอยู่ในทีมที่ผู้ใช้มีสิทธิ์ นับรวม peer และคนที่ถูกย้ายเข้ามาผ่าน emp_assignments
