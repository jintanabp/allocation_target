## แอดมิน (IT)

ผู้ใช้ใน `ALLOCATION_ADMIN_EMAILS` — หลังล็อกอิน Microsoft กด **เข้าสู่ระบบแอดมิน** โดยตรง

| กลุ่ม | ใช้ทำอะไร |
|-------|-----------|
| สิทธิ์ | ผู้ใช้, Target Sun toggle, ดาวน์โหลดสำรอง `user_access.json`, อัปเดตลำดับสิทธิ์, **สิทธิ์หน้าแอดมิน** (dev ตั้งว่าบทบาทไหนเข้าหน้าไหนได้) |
| การผูกรหัส | SL links, SKU links (งวดเป้าอัตโนมัติ — แสดงเฉพาะ SKU ที่มีเป้า > 0) |
| ข้อมูล | Inventory, แหล่งเป้า (Target Sun เท่านั้น — เลิกอ่านเป้าจาก Fabric แล้ว 6 ต.ค. 2026), **URL อ่านเป้า / ส่งผล** (preset ทดสอบหรือ Prod), แคช, **ตรวจ Target Sun รายคืน** (เฉพาะ dev) |
| ผลการดำเนินงาน | **บันทึกการใช้งาน** (ทุกความผิดพลาดมีคำอธิบาย: เกิดอะไร / น่าจะเกิดจาก / วิธีแก้ / ข้อมูลอ้างอิง · บันทึกลบไม่ได้ · มี **ตรวจจำนวนแถวหลังส่ง** ก่อน/หลัง/คาดแถวใหม่/ส่วนเกิน/ซ้อนคู่เดิม), **ผลการกระจาย** (snapshot ดู/สำรอง/ลบ), สรุปการใช้งาน, **รายงานการแก้มือ** |
| ทีม | รายชื่อพนักงานต่อ SL, **ย้ายพนักงาน** (เปิดให้แอดมินได้จากแท็บสิทธิ์หน้าแอดมิน) |
| ระบบ | **ข้อเสนอแนะจากผู้ใช้** (ข้อความจากปุ่ม 💬), **กติกาการเกลี่ย** (เปิด/ปิดกติกาไม่เคยขาย = เป้า 0), **กติกาบังคับคลัง** (บังคับคลังเดียวสำหรับกลุ่มสินค้า×ภาค×division) — เฉพาะหัวหน้าแอดมิน |

Marketing (`login_kind: marketing`) เห็นเฉพาะทีม + ผูกรหัส (ดูอย่างเดียว)

**ตั้งตำแหน่งที่เห็นข้อมูลเกินภาค** — Marketing (เห็นทุกทีมทั้งบริษัท) และ Manager ระดับเขต (ทุกภาคใน division)
ตั้งได้เฉพาะ **หัวหน้าแอดมินและ dev** · แอดมินตามขอบเขตยังตั้ง Supervisor และ Manager ระดับภาคในภาคของตัวเองได้ตามเดิม
และแก้ช่องอื่นของผู้ใช้ที่มีตำแหน่งนี้อยู่แล้วได้ (ตั้งใหม่ / ย้ายให้คนอื่น ไม่ได้)

**แท็บ「ผู้ใช้」** — แอดมินหลายคนแก้พร้อมกันได้ การแก้ของทุกคนถูกบันทึกครบ ไม่ทับกัน · ถ้าคนอื่น
เพิ่งลบหรือเพิ่มคนเดียวกันไปก่อนหน้าไม่กี่วินาที จะขึ้นว่า「ไม่พบแถว」หรือ「มีแถวนี้อยู่แล้ว」 ให้กด
โหลดใหม่แล้วดูอีกครั้ง · **ดาวน์โหลดสำรองรายชื่อ (`user_access.json`) ทุกครั้งที่แก้** แล้วส่งให้ dev
เอาเข้า git ก่อน deploy รอบถัดไป — ไม่งั้นการ deploy ที่แก้ไฟล์นี้จะเขียนทับรายชื่อบนเซิร์ฟเวอร์

**ปุ่ม ☰ มุมซ้ายบน** — พับเมนูด้านซ้ายเพื่อให้ตารางกว้างขึ้น กดอีกครั้งเพื่อกางกลับ ระบบจำค่าไว้ให้

**แท็บ「สิทธิ์หน้าแอดมิน」(เฉพาะ dev)** — ติ๊กว่าบทบาทไหนเข้าหน้าไหนได้ แล้วกดบันทึก
Dev เข้าได้ทุกหน้าเสมอ ถอดไม่ได้ · หน้า「แหล่งข้อมูล」ล็อกไว้ให้ dev เท่านั้นเพราะมีผลทั้งระบบ ·
สิทธิ์「ผู้ดูแลระบบ」มอบให้แอดมินธรรมดาไม่ได้ เพราะจะยกระดับตัวเองได้ ·
ผู้ใช้จะเห็นผลเมื่อเปิดหน้าแอดมินรอบถัดไป

**แท็บ「ย้ายพนักงาน」** — รายชื่อมาจาก 3 แหล่ง: แคชรายชื่อทีม · แคชแถวเป้า · และ
**ทะเบียนพนักงานทั้งบริษัท** สองแหล่งแรกมีเฉพาะทีมที่เคยเปิดใช้งานระบบ ส่วนทะเบียนครอบคลุมทุกคน
จึงย้ายคนของทีมที่ยังไม่มีใครเปิดได้ด้วย · ถ้ายังไม่เคยดึงทะเบียน หน้าจะขึ้นแถบเตือนบอกให้ไปกดปุ่ม
**「ดึงข้อมูลพนักงาน」ในแท็บ「สรุปการใช้งาน」** หนึ่งครั้ง (คำสั่งเดียวได้ทั้งบริษัท) แล้วกลับมากด「โหลดใหม่」

**เพิ่มรหัสที่ไม่มีในทะเบียนพนักงาน** (กล่อง ➕ เหนือตารางย้ายพนักงาน) — สำหรับรหัสที่ไม่มีตัวเซลในระบบพนักงาน
แต่มีเป้าใน Target Sun เช่น **S005 หน่วยส่งออกของ SL532** · กรอกรหัส ชื่อ เลือกทีม แล้วกด **เพิ่ม**
หัวหน้าทีมกด「โหลด」ใหม่จะเห็นรหัสนี้พร้อมป้าย **เพิ่มโดยแอดมิน** ·
เป้า เขต หน่วยขาย และคลังดึงจาก Target Sun ตามรหัสนี้ (ไม่ต้องกรอก) — งวดไหน Target Sun ยังไม่มีเป้าของรหัสนี้
จะเห็นในรายชื่อแต่ตั้งเป้าไม่ได้ · อยู่ถาวรจนกว่าจะเอาออก: ในตาราง เลือก **「— เอาออกจากทีม —」** แล้วกดบันทึก ·
รหัสที่มีในทะเบียนแล้วเพิ่มทางนี้ไม่ได้ (ระบบบอกทีมจริงให้) — ให้ค้นหาในตารางแล้วเลือกทีมแทน ·
รหัสอยู่ได้ทีมเดียวเหมือนการย้าย (กันเป้านับซ้ำตอนรวมภาค)

**ซุปบัญชีใหม่ที่ทีมตัวเองยังไม่มีพนักงาน** (เช่น SL545 — ยังไม่มีใครขึ้นกับรหัสนี้ใน Fabric) —
ตั้งบัญชีเป็น Supervisor และกรอก **ดิวิชัน + ภาค** (+ หน่วยขาย) ให้ครบ แล้วล็อกอินได้เลย:
ระบบเปิดทีมแรกในหน่วยเดียวกันให้แทน พร้อมแจ้ง「ทีม SL545 ยังไม่มีพนักงานในระบบ…」และสลับดูทีมอื่น /
มุมมองรวมภาคได้ตามปกติ · ถ้าไม่กรอกภาค จะไม่มีทีมให้ถอยไป และยังติด「ไม่พบพนักงานใต้ SuperCode」เหมือนเดิม ·
พอ Fabric มีพนักงานใต้รหัสนี้แล้ว ระบบกลับไปเปิดทีมตัวเองก่อนเอง ไม่ต้องตั้งอะไรเพิ่ม

**เป้าตั้งต้น (แท็บ「ผลการกระจาย」→ กดทีม หรือพิมพ์รหัสในช่อง「เปิด」)** — เป้าชุดที่ HQ ลงไว้ก่อนระบบเราส่งครั้งแรก
กล่องนี้โชว์สรุป + รายการที่ต่างจากเป้าปัจจุบัน · ปุ่ม **「⬇ ดาวน์โหลด Excel เป้าตั้งต้น」** ได้ทั้งชุด 2 ชีต
(เป้าหีบราย SKU พร้อมชื่อสินค้า/ราคา/เป้าบาท และเป้าเงินรายคน ทั้งคู่มีคอลัมน์เป้าปัจจุบันกับส่วนต่าง) —
อ่านอย่างเดียว ไม่เปลี่ยนเป้า ผลกระจาย หรือ Target Sun · ด้านล่างมีไฟล์คืนค่าเป้าใน Target Sun (เฉพาะทีมที่เคยส่ง)
และประวัติการส่ง · ปุ่ม「กู้คืนเป้าตั้งต้นในระบบ」เฉพาะ dev

**แท็บ「ข้อเสนอแนะจากผู้ใช้」(เฉพาะหัวหน้าแอดมิน)** — ข้อความที่ซุปส่งมาจากปุ่ม 💬 มุมขวาล่าง
เรียงใหม่สุดอยู่บน กรองตามสถานะและประเภทได้ · ตัวเลขสีบนเมนูซ้ายคือจำนวนเรื่องที่ยังไม่มีใครดู ·
กด **อ่านแล้ว** เพื่อบอกแอดมินคนอื่นว่ามีคนรับเรื่องแล้ว กด **จัดการแล้ว** เมื่อปิดเรื่องได้
กดผิดกด **กลับเป็นใหม่** ได้ · ปุ่ม **เต็ม** เปิดข้อความฉบับเต็มพร้อมเบราว์เซอร์/เวอร์ชันของผู้ส่ง ·
ทุกข้อความมีอีเมลผู้ส่งติดมาด้วย **แต่ระบบไม่ได้ส่งอีเมลแจ้งกลับให้** ต้องติดต่อกลับเอง

**แท็บ「กติกาการเกลี่ย」(เฉพาะหัวหน้าแอดมิน)** — เปิด/ปิดกติกา **「ไม่เคยขาย = เป้า 0」**
(คู่พนักงาน × สินค้า ที่ไม่เคยขายกันเลยใน 12 เดือนล่าสุดจะไม่ได้รับเป้า · ถ้าทั้งทีมไม่มีใครเคยขาย
หรือเป้าใหญ่เกินเกณฑ์ ระบบจะเฉลี่ยให้ทุกคนแทน) ทำได้ 3 อย่าง: **ปิดทั้งระบบ** (ถามย้ำก่อนเสมอ) ·
**ปรับเกณฑ์สินค้าดันเป้า** (ค่าเริ่มต้น 5 เท่า) · **ปิดเป็นรายทีม** โดยเลือกทีมแล้วกดเพิ่ม

- ทุกการแก้มีผล **เฉพาะการคำนวณครั้งถัดไป** — ผลที่ซุปบันทึกหรือส่งเข้า Target Sun ไปแล้วไม่เปลี่ยน ต้องให้เขากดคำนวณใหม่
- **ถ้าผู้จัดการกดคำนวณแบบรวมภาคแล้วมีทีมที่ถูกปิดอยู่ในรอบนั้น กติกาจะปิดทั้งรอบ** ทีมอื่นที่ยังเปิดอยู่จะไม่ได้ใช้กติกาไปด้วย · หน้าจอขึ้นบอกก่อนกดและหลังคำนวณ ทางแก้คือเลือก「แยกตามทีม」
- ปุ่ม **คืนค่าตั้งต้น** ลบค่าที่ตั้งจากหน้านี้ทิ้ง กลับไปใช้ค่าที่มากับโค้ด · แถบบนขวาบอกเสมอว่าค่าที่ใช้อยู่มาจากไหนและใครตั้งไว้เมื่อไหร่
- ค่าที่ตั้งจากหน้านี้ **อยู่รอดการ deploy** (เก็บใน `data/` ซึ่ง git ไม่แตะ)

**แท็บ「กติกาบังคับคลัง」(เฉพาะหัวหน้าแอดมิน)** — บางกลุ่มสินค้ามีเป้ากระจายอยู่หลายคลัง
ตามประวัติขาย ทั้งที่ต้องการให้สินค้าที่เลือกไว้ (ในภาค+division ที่เลือก) ถูกส่งเป้าไปที่
**คลังเดียวเท่านั้น** — เลือก **กลุ่มสินค้า** เพื่อกรอง → กด **+ เลือกสินค้าที่จะปักหมุด**
เปิดหน้าต่างเลือกสินค้า (ค้นหาได้ · ปุ่ม「เลือกทั้งหมด」เลือกเฉพาะรายการที่กำลังค้นหาอยู่
· ไม่ติ๊กอะไรไว้ก่อน ต้องเลือกเอง) → กด **ตกลง** → เลือก **ภาค** → เลือก **division** →
เลือก **คลัง** (ระบบโชว์ % หีบ/จำนวนคนต่อคลังจากข้อมูลจริงประกอบการตัดสินใจ ไม่ใช่พิมพ์เอง)
→ กด **+ เพิ่ม** → เห็นแถวใหม่ในตาราง (โชว์จำนวน SKU ที่เลือกไว้) → กด **บันทึก**

- **1 กติกาครอบได้หลาย SKU พร้อมกัน** ไม่ต้องตั้งทีละตัว — แค่ติ๊กเลือกในหน้าต่างเลือก
  สินค้าให้ครบก่อนกด「+ เพิ่ม」
- **มีผลตั้งแต่ซุปกดคำนวณ** — ตารางผลกระจายขั้นที่ 3 จะโชว์เป็นคลังเดียวตามกติกาเลย (ตรงกับ
  ไฟล์ที่ส่งจริง) ทั้งแบบทีมเดียวและ**โหมดรวมภาค** (คนจากหลายทีมในตารางเดียวก็ถูกบังคับครบ) ·
  ตอนสร้างไฟล์ส่งจริง ระบบล้างแถวคลังเก่าเป็น 0 ให้อัตโนมัติ · กติกาที่เพิ่งตั้ง ซุปต้องกด
  **คำนวณใหม่**ก่อนถึงจะเห็นผลบนตาราง
- ตั้งได้หลายกติกาต่อเนื่องกัน (เช่น สินค้าชุดเดียวกัน ปักคลังเดียวกันได้หลายภาค) —
  กดเพิ่มแล้วค่ากลุ่มสินค้า/สินค้าที่เลือก/คลังจะค้างไว้ให้ เปลี่ยนแค่ภาค/division ต่อได้เลย
- ค่าที่ตั้งจากหน้านี้ **อยู่รอดการ deploy** เช่นเดียวกับกติกาการเกลี่ย

**แท็บ「รายงานการแก้มือ」(dev, หัวหน้าแอดมิน, แอดมิน — แอดมินเห็นเฉพาะทีมในขอบเขต)** — เลือกงวด แล้วดูว่า
แต่ละทีม **แก้เลขที่ระบบกระจายให้มากแค่ไหน**: % ช่องที่แก้ · หีบที่ย้าย · สินค้าและคนที่ถูกแก้บ่อย ·
คอลัมน์ **「แก้ใน Target Sun หลังส่ง」** ขึ้นเมื่อเปิดตรวจรายคืนแล้ว · นับเฉพาะแถวที่มาจากการกระจายของระบบ
(แถวที่เป็นเป้าเดิมจาก Target Sun ไม่นับ) · ดูอย่างเดียว ไม่มีอะไรถูกแก้

**แท็บ「ตรวจ Target Sun รายคืน」(เฉพาะ dev)** — ทุกคืนระบบเทียบ Target Sun กับ **สิ่งที่เราส่งไปจริง** แล้วบอก
ว่ามีแถวไหน **ถูกแก้ / หายไป / มีคนเพิ่มเอง** หลังส่ง · **ค่าตั้งต้นปิด** (แถบสีเหลือง) ต้องเปิดเองและตั้งชั่วโมงที่รัน
(ค่าเริ่มต้นตี 2) · อ่านอย่างเดียว ไม่เขียน Target Sun · ข้ามให้เองเมื่อยังไม่ถึงวันที่ 15 (ตารางยังว่าง) หรือระบบ
อ่านกับส่งเป็นคนละที่ · อ่านไม่สำเร็จจะแจ้ง dev ในกล่องแจ้งเตือนแล้วลองใหม่คืนถัดไป · ปุ่ม **รันเดี๋ยวนี้** ถามยืนยัน
ก่อนเสมอ · กดแถวทีมเพื่อดูรายการแถวที่ต่าง · แจ้งเจ้าของ Target Sun ได้ ไม่บังคับ (อ่านอย่างเดียว) · **วันสุดท้ายของเดือน**
รันเพิ่มอีกรอบ (รอบปิดงวด ค่าเริ่มต้น 5 ทุ่ม ตั้งชั่วโมงได้ในแท็บเดียวกัน) เพื่อเห็นการแก้ที่เกิดหลังตี 2 ของวันนั้น — ขึ้นวันที่ 1 ตารางล้างเอง ตรวจย้อนไม่ได้

**กล่องแจ้งเตือน** (กระดิ่งมุมบน) — ระบบแจ้งเรื่องที่ต้องตรวจ เช่นจำนวนแถวหลังส่งไม่ตรง / ตรวจไม่ได้ / แถวซ้อนคู่เดิม
ไปที่ผู้ส่ง เจ้าของทีม แอดมินที่ดูแลทีมนั้น และ dev · ไม่มีอีเมล

มุมล่างหน้าเว็บแสดง **build** (git hash) ยืนยันเวอร์ชัน server · หน้า `/health` หัวข้อ `runtime` บอกว่า
โฟลเดอร์ `data/` อยู่ที่เดียวกันไหม (`data_dir.same`) และมีโปรเซสเดียวใช้ข้อมูลอยู่ไหม (`single_process`)
